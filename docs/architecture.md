# 架构设计：路由-检索-四Agent-复核-审计全链路

## 1. 设计目标

- 面向教师/学生/家长三种角色，同一套子图按角色收敛出不同能力面；
- 任何面向学生的输出都必须"有据可查、有人可找、有痕可审"；
- 外部依赖（模型/向量库/教务系统）全部走接口层，可替换、可降级、可离线复现。

## 2. 顶层路由图（backend/app/graphs/router_graph.py）

路由不是简单的"LLM 分类器"，而是一个带闸值的调度状态机：

```
START → narrow_by_role → discern_intent →(条件)→ dispatch | clarify_or_escalate → END
```

1. **narrow_by_role（角色收口）**：按 `ROLE_AGENT_WHITELIST` 得到候选 Agent 集合。
   权限矩阵只在这一处定义，越权意图在分类之前就被排除在候选外；
2. **discern_intent（辨意）**：联网模式调用校内 BERT 意图服务（独立小模型端点，
   不占大模型配额）；离线模式用确定性词频评分近似 softmax 置信；
3. **派发闸值**：`confidence ≥ 0.92` 且意图在白名单内才自动派发；
4. **clarify_or_escalate**：不达标先给澄清话术（最多 2 轮，轮数由客户端回传状态携带），
   仍不明确则打包上下文推送教师复核队列——路由层永不"猜着派发"。

每个节点向 `audit_trail` 追加 `(node, decision, detail, ts)`，整条决策链可回放。

## 3. 四个子图

| 子图 | 节点链 | 关键纪律 |
| --- | --- | --- |
| lesson_prep | 课标检索→大纲→课件→组卷→草稿打包 | 产物永远是教师草稿；自创题必须带评分要点才采纳 |
| qa | 缓存查询→改写→混合检索→带引用生成→双闸门校验→(收紧重生成/拒答) | 引用回查+一致性校验，不过即拒 |
| grading | 客观规则判分→主观要点评分→分流→评语建议稿 | 客观题零模型；低置信/申诉转教师；评语无自动下发 |
| profile | 作答读取→掌握度计算→预警规则→LLM归因→报告 | 预警只由规则触发，LLM 不贴标签 |

子图间不共享业务状态，仅通过路由图的 `result_input` 投影传参，避免隐式耦合。

## 4. 检索链路（backend/app/retrieval/）

```
query → BGE-M3 嵌入(或哈希n-gram降级) ┐
                                      ├→ RRF(k=60) 融合 → Reranker 精排 → top-k 子块
query → 自研中文BM25(字bigram+整词)   ┘                         │
                                          父块回填 parent_text ←┘
```

- **元数据过滤（学段×学科×来源）贯穿向量路与词面路**，防止跨学段证据混入；
- **父子块**：子块参与召回（语义聚焦），父块只进向量库（不参与召回），
  命中子块后回填父块全文给生成节点（上下文完整）；
- 重排失败自动回退 RRF 顺序，检索永不因单点故障阻塞答疑。

## 5. 安全与复核（backend/app/safety/ + routes_admin）

- **pii_masker**：接入层前置脱敏闸门，映射表仅存校内、会话销毁即删；
  疑似不可靠 PII（如超长数字串）→ `ok=False` → 直接拒答；
- **schema_validator**：结构化输出（评分/大纲 JSON）入库前校验，非法结构按低置信处理；
- **citation_checker**：答案中每个【来源】与本轮证据集回查，页码/题号坐标命中任一证据即有效；
- **risk_policy**：教师草稿 / 学生可见 / 成绩评语三级。学生可见需四项检查全过，
  失败降级为草稿并进复核队列；成绩评语在系统层面不存在自动下发路径；
- **复核闭环**：`/api/v1/admin/review-queue` 消费复核任务，教师签发定稿后
  经 `MirrorCache.put(reviewed=True)` 写回镜像缓存，成为后续同类问题的可信答案。

## 6. 镜像双缓存（backend/app/db/cache.py）

- 写回纪律：仅 **教师复核定稿** 或 **与既有缓存问题相似度 ≥ 0.92 的再验证** 可写回；
- 条目绑定 `corpus_version`，课程修订即整体失效；
- 热层 Redis（可选）+ 暖层进程内/数据库，答疑子图首节点即查缓存，命中直接出答案
  ——这是"首 Token < 1.5s"与自助解决率的主要工程抓手。

## 7. 模型网关（backend/app/gateway/）

- OpenAI 兼容协议，不绑定厂商；场景化调用（router/lesson/qa/grading/profile 白名单）
  支撑分场景统计与独立限流；
- 令牌桶限流 + 仅对 429/5xx/网络错误的指数退避重试；
- 语义缓存（模型×场景×规范化消息哈希）与业务镜像缓存分层解耦；
- mock 模式支持 `mock_example` 注入：各子图在离线时提供本场景确定性算法结果，
  保证全链路可测试、可演示、可回归。

## 8. 存储

- PostgreSQL（SQLAlchemy）：学校/用户/班级/任务/**产物版本链**/审计日志；
  学生仅存脱敏代号，任务仅存输入哈希；
- Milvus：HNSW/IP 索引，标量字段承载引用坐标与过滤维度；
- Redis：缓存热层与会话存储（部署在校内）。
