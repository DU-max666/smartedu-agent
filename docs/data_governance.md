# 数据治理：多源接入、切片规范与 badcase 归因闭环

## 1. 多源数据接入

| 来源 | 入口 | 适配器 |
| --- | --- | --- |
| 教材/课标 Markdown 电子化 | `data/pipeline.py::load_dir` | 直读 |
| 纸质教材扫描件 | `OcrAdapter.read_image` | PaddleOCR（可选依赖，缺库给出安装指引） |
| 课堂录音/答疑录音 | `AsrAdapter.transcribe` | Whisper（可选依赖） |
| 题库 | `tools/question_bank.py` | 内置样例 + 可替换为学校题库 API |
| 教务作答记录 | `tools/academic_affairs.py` | mock 数据源 / 校内教务 HTTP 接口 |

所有外部系统一律经接口层进入，`run()` 契约稳定，替换实现不改调用方。

## 2. 入库五步（管道）

```
接入 → 元数据抽取(front-matter) → 清洗去重 → 切片 → 入库
```

- **元数据**：`doc_id / grade / subject / source_type / page_start`，
  是检索过滤与引用坐标的事实来源；缺 `doc_id` 用文件名兜底；
- **清洗**：控制字符剔除、空白归一；**去重**按正文 SHA1，重复样本拒收并计数；
- **入库**：子块进"向量+BM25"双索引；父块只进向量库供回填，不参与召回。

## 3. 切片规范

三种切分器按 `source_type` 路由：

1. **父子块**（textbook/curriculum）：
   - 父块 = 标题层级段落；子块 = 句子窗口（默认 ≤240 字，句间重叠 1 句）；
   - 规范：子块必须能独立成句表意；单句超限允许保留（不可再分原则）；
2. **表格结构化**（table）：表头与每一行绑定为一条记录（`列名:值; ...`），
   杜绝滑窗把表格拦腰切断；
3. **对话轮次**（dialogue）：学生/家长的问与紧随的教师/老师答配成一对整轮入库，
   保留真实"问法多样性"，供答疑改写节点做指代与口语化参考。

引用坐标约定：教材类给 `page`，题库类给 `question_no`，生成侧统一
【来源:doc_id | 页码 | 题号】格式，回查侧容忍"第12页/12"两种写法。

## 4. badcase 归因机制

评测失败不是"改改提示词再跑"，而是按四类根因分流治理
（`eval/badcase_analysis.py` 自动归因 + 处置建议）：

| 根因 | 判定信号 | 处置动作 | 责任环节 |
| --- | --- | --- | --- |
| retrieval_miss | 期望文档未进证据集 | 补语料 / 调子块长度 / 重跑 build_corpus | 数据管道 |
| generation_hallucination | 证据命中但引用/一致性失败 | 收紧生成提示词引用纪律；核对坐标入库 | 提示词/切片 |
| prompt_ambiguity | 路由意图判错 | 补意图样本、复核派发闸值 | 路由/BERT |
| data_quality | 脱敏/敏感词/结构校验失败 | 回查清洗规则与正则；必要时下线坏样本 | 治理规则 |

**下线通道**：确认坏样本后 `python scripts/build_corpus.py --retire <doc_id>`，
向量索引、BM25 与语料映射同步清理；若该文档答案已进入镜像缓存，
因缓存条目绑定 `corpus_version`，随版本升级整体失效，不会出现"坏语料喂出定稿答案"的死角。

## 5. 未成年人数据红线

- 学生明文身份（姓名/学号/证件/联系方式）**不允许进入任何语料与日志**；
  接入层 PII 闸门在入库与调用两侧同时生效；
- 教务数据只以脱敏代号 `S-xxxx` 参与计算，`academic_affairs` 工具对明文身份直接拒收；
- 映射表只存校内会话存储，会话结束即销毁；审计日志只记录决策与摘要，不落原文。
