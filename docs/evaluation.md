# 评测与上线验证方案（evaluation）

本文说明慧学平台从离线评测到线上灰度的完整验证链路。核心思路是**三段式闸门**：
离线评测集达标 → 影子对比不劣化 → 小流量灰度可回滚。任何一段不满足，都不进入下一段。

## 1. 离线评测（eval/）

### 1.1 评测集构成

`eval/eval_set.jsonl` 共 30 条自创样例，按场景分五组：

| 前缀 | 场景 | 条数 | 断言类型 |
|------|------|------|----------|
| R | 意图路由 | 8 | 派发目标子图 / 澄清不派发 |
| Q | 答疑 | 8 | 引用存在性、证据坐标、拒答行为 |
| G | 批改 | 8 | 客观题精确判分、主观题分数区间、低置信转复核 |
| P | 学情 | 2 | 薄弱知识点识别、掉队预警触发 |
| S | 安全 | 4 | PII 拒答、敏感词拦截、越权收敛 |

### 1.2 运行方式

```bash
python eval/run_eval.py            # 全量跑，输出指标汇总
python eval/run_eval.py --filter Q # 只跑答疑组
```

`run_eval.py` 直接调用路由图与四个子图（离线 mock 模式，无需外部密钥），
逐条执行断言并汇总为指标表；失败条目写入 `eval/results.jsonl` 供
`badcase_analysis.py` 做四类归因（retrieval_miss / generation_hallucination /
prompt_ambiguity / data_quality）。

### 1.3 指标口径

与 README 承诺一致，离线回归必须保持：

- 答疑自助解决率 ≥ 80%（有引用且通过一致性校验的答案占比）
- 客观题判分正确率 ≥ 99%（零模型精确匹配，理论上 100%，留出归一化边界样例）
- 学情薄弱知识点识别一致率 ≥ 90%（与人工标注对照）
- 安全组 4 条全部拦截，0 条泄漏

## 2. 影子对比（Shadow Comparison）

新链路（多智能体 + 混合检索）上线前，**不承接真实流量返回**，只做同流量双跑：

```
学生/教师请求 ──► 旧链路（单轮 RAG）──► 实际返回给用户
        │
        └──────► 新链路（影子模式）──► 结果只写对比日志，不返回
```

### 2.1 实现要点

- 影子调用走独立线程池，超时 8s 即放弃，绝不阻塞主链路；
- 影子流量按 10% 采样，日志落 `agent_task` 表并标记 `shadow=True`；
- 对比维度：
  1. **答案一致率**：新链路答案与旧链路在判分/结论层面是否一致（客观题精确比对，主观题要点重合度 ≥ 0.6 记一致）；
  2. **引用覆盖率**：新链路答案带有效引用的比例（目标 ≥ 95%，旧链路无此指标）；
  3. **拒答率差**：新链路拒答而旧链路作答的请求，逐条人工抽检，确认是"该拒"而非"检索失败"；
  4. **时延分位**：P50 / P95 / 首 Token 时间，新链路 P95 不得劣于旧链路 20% 以上。

### 2.2 通过标准

影子期建议 ≥ 2 周、覆盖 ≥ 5000 条真实请求。四项指标全部达标且
badcase 归因中 retrieval_miss 占比 < 15%，方可进入灰度。

## 3. 灰度验证（Canary Rollout）

### 3.1 放量节奏

按**班级维度**灰度（而非用户百分比），保证同一班级体验一致、便于教师配合反馈：

| 阶段 | 范围 | 时长 | 准出条件 |
|------|------|------|----------|
| C1 | 1 个试点班（教师主动报名） | 1 周 | 无安全事故；教师复核队列积压 < 20 条 |
| C2 | 同年级 3 个班 | 1 周 | 自助解决率 ≥ 75%；差评率 < 5% |
| C3 | 全学段 20% 班级 | 2 周 | 自助解决率 ≥ 80%；主观题一致率 ≥ 85% |
| C4 | 100% | — | 指标连续 7 天稳定 |

### 3.2 指标看板

灰度期每日自动汇总（按 `agent_task` + `audit_log` 聚合）：

- 派发准确率（澄清率、错误派发率单独列）
- 答疑自助解决率 / 引用有效率 / 拒答率
- 批改：客观题正确率、主观题转复核率、教师改判率（改判即不一致信号）
- 学情：预警命中率（教师确认 / 总预警）
- 性能：P95 端到端时延、首 Token < 1.5s 达标率、网关 429 重试率
- 安全：PII 拒答数、敏感词拦截数、越权请求数（后两项必须为 0）

### 3.3 回滚条件与开关

满足任一条件**立即回滚**到旧链路（配置开关 `ROUTER_MODE=legacy`，秒级生效）：

1. 任何一条学生可见内容出现未脱敏 PII 或越权信息（一票否决）；
2. 单日教师改判率 > 15%（主观题一致率崩塌信号）；
3. P95 时延连续 2 小时 > 8s 或错误率 > 2%；
4. 复核队列积压 > 200 条且增速未收敛。

回滚后 badcase 仍照常归因入库，修复走第 1 节离线回归 → 第 2 节影子 → 重新灰度。

## 4. 性能压测

`deploy/locustfile.py` 模拟答疑 : 健康检查 = 8 : 1 的真实流量配比：

```bash
locust -f deploy/locustfile.py --headless -u 4000 -r 100 \
  --host http://api:8000
```

验收口径：4000 并发下 P95 < 3s、首 Token < 1.5s（流式接口）、错误率 < 0.1%。
压测环境需开启 Milvus 与 Redis 真实依赖；纯 mock 结果仅作链路功能参考，
不作为容量结论。

## 5. 持续评测

- 每次提示词 / 检索参数变更，必须先过 30 条离线集回归（CI 阻断）；
- 每月从复核队列抽样 50 条真实 badcase 追加进评测集，防止指标与线上脱节；
- 评测集只增不改：修改既有条目断言需在评审中说明理由并留档。
